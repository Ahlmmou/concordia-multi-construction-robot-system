# Step 1: omit unused Nav2 debugging

Both normal fleet Nav2 parameter files now set FollowPath.debug_trajectory_details, publish_evaluation, publish_trajectories and publish_cost_grid_pc to false. Cost-grid publication was already false; it is explicit to retain that setting. Detailed no-legal-trajectory error diagnostics and unused evaluation/trajectory debug publications are disabled. The normal error handling, trajectory scoring and navigation critics remain intact. RViz paths, scans, costmaps, footprints and fleet TF/relay configuration are preserved.

Semantic YAML comparison against the preceding commit verified that only these four options changed. Speeds, acceleration, controller sampling, costmaps, footprint sizes, clearances and fleet goal-update timing are identical.

Live application: the fleet initially reported STOPPED/IDLE. Supervisor stop was acknowledged, all five zero motor commands and released action ownership were verified. Each robot's navigation lifecycle manager RESET completed; the four options were set while controllers were unconfigured; each STARTUP completed. All five controller states were ACTIVE (3), all 20 inspected booleans were false, and the fleet remained STOPPED as initially observed. Gazebo and RViz were retained.

These DWB options are cached during configure, so changing live parameter values alone is insufficient. The next normal launch reads the committed configurations.

Timing in matched stopped/idle conditions: before, 4.3 simulation seconds in 15.011 wall seconds (RTF 0.286); after, 4.0 simulation seconds in 15.004 wall seconds (RTF 0.267). This short uncontrolled observation does not establish a performance gain; the after sample was slower. No before/after moving benchmark was performed. Disabling detailed diagnostics primarily helps when failures generate logs or debug outputs have subscribers, so no substantial speedup is claimed.

The first timing probe had an incompatible /clock reliability QoS and was discarded before applying debug changes. The corrected probe used sensor-data QoS. RViz MCP was mock; observations used live rclpy services/topics. Evidence is in debug_disabled_live_2026-10-13.json.

Reference checked for ROS Humble configure-time reads and debug behavior: https://api.nav2.org/nav2-humble/html/dwb__local__planner_8cpp_source.html and https://api.nav2.org/nav2-humble/html/publisher_8cpp_source.html.
