# Elevator tracing reference

Open `config/EVfloor9_elevator_tracing.xcf` in GIMP. The selected **Elevator walls - six unequal shafts** layer contains the traced walls. The original drawing layer is preserved. The detailed plan is a locked reference at 45% opacity in Multiply mode, so its white background does not obscure the aligned map. It is hidden for the final export. The Gazebo reference and original map remain available as hidden layers.

Reference: [dev branch floor plan](https://github.com/Pplll-pppl/concordia-multi-construction-robot-system/blob/a8a587547c581289ee31312957f66c8b1bdf311e/config/EVfloor-Floor-Plan-Level-7-test.pgm), as selected by that branch's `EVfloor-Floor-Plan-Level-1.yaml`. Its bytes exactly match the existing repository copy (SHA-256 `eff5a59c73e723a3ff9da6e788d2bc900ff82286932048ab3ff119be0d481449`), which was used without modification.

The 3508 × 2480 reference is placed at (0, 500) pixels on the 4215 × 2980 aligned canvas, without resampling. Shared stairwell and outer-wall landmarks support this offset; the source and Gazebo outlines still have small local differences. This is a tracing guide, not a claim that the detailed source is an exact survey of Gazebo. The source does not cover the top 500 rows of the aligned canvas.

The underlying base map preserves the previous formation map and stair protection. Six shaft interiors were traced from the reference's enclosed free regions, preserving unequal widths and stepped corners. Black wall bands extend seven pixels outward from those interiors, including shared partitions. The inter-bank passage remains free. `config/EVfloor9_elevator_walls.png` is the separate transparent wall layer; the formation-map generator now composites its dark pixels with alpha at least 128 into the protected map. The binary GIMP composite exactly matches the regenerated map. Existing occupied cells remain occupied. The former unsaved GIMP state was snapshotted to `/tmp/elevator-before-drawing.xcf` before adding the new layer.

Validation: 34 targeted tests pass, including six separately enclosed shaft interiors, a clear passage, retained stair exclusion and existing fleet velocity-gate tests. The live `/map` exactly matches the export; all 16,652 elevator wall cells are occupied in the received tb1, tb2, tb3 and tb5 global costmaps. No tb4 global costmap was received during the observation. Gazebo ran headlessly with an advancing observed `/clock` (182.4 to 212.3 seconds), while RViz's GUI displayed both banks with their inflated obstacle boundaries. RViz MCP confirmed a live connection and the enabled `/map` display; its screenshot operation was unavailable, so a native desktop capture supplied visual evidence. Gazebo MCP continued to report zero time/iterations and was not used as clock evidence. See `elevator_live_map_check.json` and `elevator_rviz.png`.

The supervisor held every robot at zero commanded motion because tb4's gated Nav2 velocity smoother was not ready. No navigation goal was sent and no ownership, collision, clearance or velocity-gate settings were changed. This validates map loading and obstacle classification, not a successful formation mission. Gazebo physical geometry is unchanged by this map edit.
